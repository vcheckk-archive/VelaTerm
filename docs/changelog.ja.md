## v0.1.100 — 2026-08-10

### AI エージェント

- **Kiro CLI が第一級のセッションタイプになりました。** Kiro のセッションはツリーに独自のノードを持ち、Kiro 自身の lifecycle hooks に基づく正確な作業中・待機中の状態ドット、ターン終了時の通知、ノードを開き直したときの同じ会話の自動再開、起動引数と確認スキップの切り替え、vspawn 経由の起動に対応します。ほかのエージェントで既に使えていたものが一通り揃いました。VelaTerm は既定の Kiro エージェントを独自の `vlx-term` エージェントとして複製し、その複製にだけ観測専用の lifecycle hooks を追加して起動します。利用者自身のエージェントファイルは書き換えないため、プロンプト、ツール、MCP サーバーはそのまま引き継がれます。Kiro には権限確認の hook がないため、承認を待っている間も状態ドットは作業中のままです。

### 修正

- **ターミナルから起動したプログラムが AppImage 自身の環境を引き継がなくなりました（Linux）。** AppImage のランチャーは `PYTHONHOME`、`PYTHONPATH`、`PERLLIB`、`QT_PLUGIN_PATH` と GStreamer のプラグインパスをバンドルの一時マウントディレクトリへ向け、`PATH` と `LD_LIBRARY_PATH` の先頭にもバンドル内のディレクトリを差し込みます。ターミナルは自分の環境をそのまま起動する shell へ渡すため、システムの `python3` が標準ライブラリをバンドル内に探しに行って起動すらできず、動的リンクされた他のプログラムもシステム側ではなくバンドル内のライブラリを読み込んでいました。VelaTerm は shell や外部ツールを起動する前にこれらのバンドル由来のパスを取り除き、利用者自身が設定した値には手を触れません。`APPDIR` と `APPIMAGE` は残るため、AppImage から動いているかを確認するプログラムはこれまでどおり判定できます。影響を受けるのは AppImage 版だけで、deb パッケージ、macOS、Windows の動作は変わりません。

## v0.1.99 — 2026-08-09

### ターミナル

- **Shift+Enter が送信ではなく改行になりました。** ターミナルには修飾キー付き Enter を表す符号がないため、Claude Code や Codex などのエージェント CLI には通常の復帰文字だけが届き、入力の途中でプロンプトが送信されていました。VelaTerm は ESC+CR を送るようになり、これらのツールが iTerm2 のキーマッピングで想定している系列と一致します。これで複数行の入力が可能になりました。これまでカスタムキーハンドラーが導入されていなかった macOS も対象です。入力メソッドの変換中は従来どおりで、Enter は候補の確定に使えます。

### プロジェクトと整理

- **セッション単位で状態を再判定。** 状態フィルターが有効なペインでは、セッションのメニューに「状態を更新」が追加されました。そのペイン自身の条件でそのセッションだけを再評価して表示・非表示を切り替え、他のセッションはそのまま残ります。この操作はメニューを開いたペインに属するため、再帰的に分割していても別のペインの条件が使われることはありません。結果はペインごとに保存され、再起動後も復元されます。
- **マークの解除がワンクリックに。** すでに適用されている絵文字をもう一度選ぶと解除されるようになり、専用の解除項目とその区切り線は不要になりました。フィルターボタンの絵文字バッジも削除しました。ボタンのハイライトでマークフィルターが有効なことは分かり、どの絵文字かはメニューに表示されています。

### 修正

- **Linux AppImage のデスクトップ統合がどの環境でもインストールできるようになりました。** 同梱アイコンがビルドマシンの絶対パスへのシンボリックリンクだったため、アプリ自体は正常に動作するのに Gear Lever や AppImageLauncher などのツールがアイコンを取り出せませんでした。リンクを相対パスに変更しています。あわせて、実行ファイルだけでなく同梱ライブラリも計測した結果、glibc の要件を 2.35 に訂正しました。デスクトップ版が対応する最も古いディストリビューションは Ubuntu 22.04 になります。
