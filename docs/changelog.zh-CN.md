## v0.1.100 — 2026-08-10

### AI 智能体

- **Kiro CLI 成为一等公民会话类型。** Kiro 会话在树里有自己的节点，状态点由 Kiro 自己的生命周期 hooks 驱动，如实反映工作中与等待处理；一个回合结束会发通知；重新打开节点自动接回同一段对话；启动参数、跳过确认开关、经 vspawn 派生子会话也都齐了——其它智能体已有的能力，Kiro 现在都有。VelaTerm 把你的默认 Kiro agent 克隆成自己的 `vlx-term` agent，只在副本上加一份只观察、不干预的生命周期 hooks 再启动它，你自己的 agent 文件全程不动，提示词、工具和 MCP 服务器原样带过来。Kiro 没有权限请求 hook，所以它等你批准的时候，状态点仍然显示为工作中。

### 修复

- **终端里启动的程序不再继承 AppImage 自己的环境（Linux）。** AppImage 的启动器会把 `PYTHONHOME`、`PYTHONPATH`、`PERLLIB`、`QT_PLUGIN_PATH` 和 GStreamer 的插件路径指向包内的临时挂载目录，并把包内目录插到 `PATH`、`LD_LIBRARY_PATH` 的最前面。终端会把整个环境交给它启动的 shell，于是系统的 `python3` 跑到包里去找标准库，根本起不来；其它动态链接的程序也会优先加载包里的那份库，而不是系统的。现在 VelaTerm 在启动 shell 或外部工具之前先把这些包内路径剥掉，你自己设的值保持不动。`APPDIR` 和 `APPIMAGE` 仍然可见，靠它们判断自己是不是从 AppImage 启动的程序照样拿得到答案。只有 AppImage 版本受影响，deb 包、macOS 和 Windows 行为不变。

## v0.1.99 — 2026-08-09

### 终端

- **Shift+Enter 换行，不再直接提交。** 终端协议里没有「带修饰键的 Enter」这种编码，因此 Claude Code、Codex 这类智能体命令行收到的只是一个普通回车，话还没写完就被发了出去。现在 VelaTerm 改发 ESC+CR，与这些工具在 iTerm2 上配置键位映射后期望的序列一致，多行输入终于可用——macOS 也包含在内，此前那里根本没有安装自定义按键处理。输入法组词期间不受影响，Enter 仍用于上屏候选词。

### 项目与组织

- **单个会话的状态可以单独刷新。** 在启用了状态筛选的窗格中，会话菜单新增「刷新状态」，只按该窗格自己的条件重新判断这一个会话并决定去留，其余会话原地不动。该操作归属于菜单所在的窗格，因此递归切分时不会误用其它窗格的筛选条件；结果按窗格分别保存，重启后恢复。
- **清除标记只需点一下。** 再次选择已生效的表情即可取消，原先单列的清除项和分隔线随之移除。筛选按钮上的表情徽章也一并去掉：按钮高亮已经说明表情筛选处于启用状态，具体是哪个表情菜单里写着。

### 修复

- **Linux AppImage 的桌面集成在任何机器上都能安装。** 打包进去的图标是一个指向构建机绝对路径的符号链接，因此 Gear Lever、AppImageLauncher 这类工具无法提取图标，尽管程序本身运行正常。现在改为相对链接。glibc 要求也更正为 2.35——此前只测了主程序，未计入随包分发的库——因此桌面端支持的最老发行版为 Ubuntu 22.04。

## v0.1.98 — 2026-08-02

### AI 智能体

- **Grok Build 成为 VelaTerm 的一等智能体。** 现在可以安装、启动和续接 Grok 4.5；稳定的会话 ID、官方 lifecycle hooks、准确的工作与权限状态、合并后的转录、用量详情和随主题变化的官方图标，在桌面端、浏览器端和移动端保持一致。

### 项目与组织

- **把项目左栏切分成彼此独立的工作视图。** 任一树窗格都能继续向下切分，并在重启后恢复各自的搜索、状态与表情筛选、折叠状态和分隔比例。所有窗格仍是同一份后端项目树的投影视图，编辑会同步生效，不会复制业务数据。
- **标记并筛选节点时不再丢失上下文。** 项目、分组和会话都可以添加表情标记。命中标记的容器会保留完整子树；状态成员在操作期间保持稳定，同时支持动态增加和手动刷新；状态与表情条件按并集合并。
- **直接创建空项目。** 选择父目录并校验名称后，可在同一流程中创建并导入文件夹。中途导入失败时只会重试导入，不会重复创建目录。

### 界面

- **细节交互更顺手。** 临时终端标签在保存为正式会话前即可重命名；普通输入框会关闭移动键盘的自动首字母大写，同时不改变终端输入行为。

## v0.1.97 — 2026-07-25

### AI 智能体

- **会话不会再卡在“工作中”。** Codex 通过各自独立的短命进程上报工具活动和回合结束，回调到达顺序可能颠倒，导致已经结束的回合仍显示为工作中。现在会丢弃在自身回合结束之后才到达的中途上报，并新增会话结束 hook，覆盖没有发出完成事件就退出的会话。
- **被打断的回合几秒内即可恢复正常。** 按下 Esc 或遇到流式错误时，Claude 与 Codex 的回合结束时完全不会发出完成回调。现在终端连续静默六秒后会安静地把这类会话校正为等待中，且不会弹出“已回复”通知。

### 界面

- **macOS 上的分屏快捷键更可靠。** 向右分屏（Cmd+D）和向下分屏（Cmd+Shift+D）现在同时注册为原生 Terminal 菜单命令，macOS 不会再在 VelaTerm 收到之前拦截这组按键。
- **一次按键只保存一次文档。** Cmd+S 之前会被全局快捷键和聚焦中的编辑器同时处理，可能在一次按键中把同一个文件写入两次。

## v0.1.96 — 2026-07-23

### AI 智能体

- **Codex 状态只信任 lifecycle hooks，不再依赖终端猜测。** 新版 Codex 会话现在只使用官方 lifecycle hooks 作为活动状态来源。`SessionStart` 握手会验证回调链路；缺少回调时明确显示“状态不可用”；终端文字或输出活动也不会再覆盖工作、待确认或已完成状态。
- **每个回合结束后更及时地刷新 Codex 用量。** Info 面板会立即显示本地 rollout 快照，再与实时速率额度校准；Codex 写完最终 token 快照后还会补一次刷新，并忽略来自旧会话的延迟响应。

### 界面

- **macOS 上的项目树命中更可靠。** 虚拟行不再依赖合成器 transform，避免滚动或树更新后 WKWebView 保留过期命中坐标，导致悬停、点击或拖拽落到另一行。

## v0.1.95 — 2026-07-21

### AI 智能体

- **Kimi Code 和 Zoo Code 加入会话树。** VelaTerm 现在可以启动、续接、安装并配置这两种智能体。Kimi 使用官方生命周期 hooks 权威上报工作、权限和等待状态；Zoo Code 保持稳定任务标识，并在缺少外部 hooks 时使用终端检测。
- **实时刷新 Codex 用量。** Info 面板现在可以主动查询 Codex app server 获取最新速率额度，同时保留本地 rollout 快照作为兼容回退。

### 项目与终端

- **使用 `vela <path>` 打开项目。** 发布版现在可以安装类似 VS Code 的 shell 命令；再次调用会把项目转交给已有 VelaTerm 窗口，而不是打开重复实例。
- **可见、可取消的 Git 克隆。** “克隆项目”现在显示 Git 阶段、百分比与耗时，可提示长时间无进展，并能取消整个 Git 进程树且不留下半成品目录。界面错误和审计日志会隐藏凭据与查询 token。

### 界面与可靠性

- **更清晰的后台会话控制。** 后台标签菜单会显示每个会话的实时状态，超限弹窗也可以一次结束多个已选标签。
- **更安全的应用生命周期与更新说明。** 退出前会确认是否停止运行中的会话；Codex lifecycle 的精确身份优先于含糊的 rollout 扫描；自动更新说明支持所有内置界面语言。

### 本地化

### 图片和文档

- **在 macOS 上可靠地粘贴图片路径。** 当 WebKit 没有把复制的图片暴露为文件时，VelaTerm 现在会从系统剪贴板读取图片，并仍将其作为文件路径上传，而不会静默退回智能体原生的图片占位符。远程窗口会始终显示图片粘贴设置、解释为何必须使用文件路径模式，并禁用不可用的原生选项。
- **将图片粘贴到源文档。** 源代码编辑器现在支持粘贴剪贴板图片。已保存的 Markdown 文档会把图片存放在文档旁的 `assets/` 目录中，并插入可移植的 Markdown 图片语法；未保存的草稿会嵌入图片数据，避免临时文件清理时丢失。

### 界面

- **上下文菜单始终可见并准确定位。** 在右侧边缘附近打开的菜单会被正确测量和调整位置。右键单击树节点时，现在只会高亮菜单目标而不改变已有选择；分组菜单中也新增了作用于该分组的终端入口。
- **更清爽的编辑效果和状态标签。** 源代码文本不再为 HTML 注释等字符序列渲染箭头状字体连字；用量百分比会明确标注为已使用；宿主 WebView 无关的原生上下文菜单也不会再出现在 VelaTerm 自有菜单后方。

### 修复

- **Codex 保持在普通终端历史记录中。** 由 VelaTerm 启动的 Codex 会话现在使用内联终端模式，因此按 Esc 中断或返回时，不会再切换终端屏幕缓冲区并让回滚视图跳到顶部。用户自己的 Codex 配置不会被修改。
